# GitHub Comment from Session

セッション中の会話を一次資料として、GitHub の issue / PR コメント・レビュー返信の本文を組み立てるスキル。

**なぜこの形なのか**: 結論だけでは「なぜそうなったか」が落ち、後から読む人が同じ検討をやり直すことになる。かといって会話ログを貼り付けると、読み手は他人の作業記録を最初から追う羽目になり、結局読まれない。だから **本文は結論、折りたたみは背景を理解できる最小限のまとめ** という形をとる。会話ログはそのまとめを書くための材料であって、成果物ではない。

## ワークフロー

### Step 1: 何へのコメントかを確定する

投稿自体はユーザーがブラウザで行うので番号を調べる必要はないが、**種別によって書き方が変わる**ため、どれなのかは押さえる。曖昧なら聞く。

| 種別 | 書き方の違い |
| --- | --- |
| issue コメント | 課題そのものへの報告・提案。背景から書く必要がある |
| PR コメント | レビュアー向け。diff から読めることは書かず、判断の理由に絞る |
| レビューコメントへの返信 | 指摘への応答。「直した」か「直さない、理由は〜」を最初に出す |

対象の PR / issue が会話中に出てきていない場合、現在のブランチから当たりを付けて確認する:

```bash
gh pr view --json number,url,title
```

### Step 2: 会話ログを材料として取り出す

同梱スクリプトで transcript から会話を取り出す。思考ブロック・ツール呼び出し・ツール結果・system-reminder は自動で落ちる。

```bash
python3 <skill-dir>/scripts/extract_transcript.py --quote > "$TMPDIR/session-log.md"
```

主なオプション:

- `--list` — セッション一覧（日時と ID）を表示。別セッションの内容を引くときにまず使う
- `--session <id|path>` — 対象セッションの指定（既定は最新 = 通常は今のセッション）
- `--last-n <N>` — 末尾 N 発言だけ。長いセッションの終盤だけ引きたいときに
- `--since <ISO8601>` — 指定時刻以降だけ
- `--include-sidechain` — subagent の会話も含める（既定は除外）
- `--quote` — Markdown の引用記法 `>` を付ける
- `--format json` — 発言単位の構造化出力。取捨選択を自分でやりたいとき

**今のセッションを引く場合の注意**: transcript はライブで書かれているため、末尾にはこのスキルを起動した指示そのものが載る。

ここで得るのはあくまで下書きの材料。この出力をそのままコメントに貼らない。

### Step 3: 背景のまとめに凝縮し、外に出せない情報を落とす

#### 3-1. 会話を「背景」に書き直す

会話ログを読み、**それを読まなくても経緯が分かるまとめ**に書き直す。発言の羅列ではなく、地の文と箇条書きで。折りたたみを開いた人が 30 秒で追える量、目安 10〜20 行に収める。

含めるもの:

- 出発点。何が問題だったのか、何を頼まれたのか
- 途中で分かった、結論を左右した観察（数値・エラーメッセージ・仕様の制約など）
- 決めたことと、その決め手
- 検討したが採らなかった選択肢と、採らなかった理由。ここが抜けると読み手は同じ案を再提案してくる

落とすもの:

- 結論に影響しなかった試行錯誤、ツール実行の失敗と再試行
- 誰がいつ何を言ったかという進行そのもの。読み手が知りたいのは経緯であって議事録ではない
- 投稿先のリポジトリと無関係な話題

**発言をそのまま引用するのは、言い回し自体が根拠になるときだけ**にする。ユーザーが方針を決めた一言（「それはやめて、〜でいく」）などが該当する。その場合も 1〜2 行の引用に留め、まとめの中に埋め込む。

#### 3-2. ローカル環境の情報を落とす

まとめに書き直しても、**手元の作業に出てきたパスや識別子はそのまま持ち込まれやすい**。文章として自然に読めてしまうぶん見落とすので、この工程を独立して置いている。

書き出す前に次を洗い出して、置き換えるか、その記述ごと削る:

| 出るもの | 対処 |
| --- | --- |
| 一時ディレクトリ（`/tmp/...`、`$TMPDIR` の展開結果、スクラッチパッドのパス） | 削るか `<tmp>/comment.md` のように伏せる |
| ホームディレクトリを含む絶対パス（`/Users/<name>/...`） | リポジトリ相対パスに直す |
| worktree の置き場所、ローカルブランチの試行錯誤 | 読み手に無関係なので削る |
| API キー・トークン・社内固有の URL・第三者の個人名 | 削る。伏せ字にしても書いた事実は残るので、迷ったら記述ごと落とす |

機械的な洗い出しには grep が早い:

```bash
grep -nE '/Users/|/tmp/|\$TMPDIR|/private/var/folders' "$TMPDIR/comment.md"
```

GitHub のコメントは削除しても編集履歴とメール通知に残る。投稿前が唯一の防波堤だと考えて扱う。

### Step 4: 本文を組み立てる

次の構成で書く。

```markdown
🤖 <agent> (<model>)

<結論・依頼・報告を 1〜3 文で。読み手が最初の 1 行で「自分が何をすべきか」を判断できるように>

## 経緯 / 根拠
<なぜこの結論になったかを箇条書きで数行。diff やコミット履歴を読めば分かることは書かない>

<details>
<summary>背景</summary>

<Step 3 で書いたまとめ。10〜20 行>

</details>
```

守るべき点:

- **1 行目に署名**。グローバルルールで、コメントは 1 行目に `🤖 <agent> (<model>)` を置くと決まっている（issue / PR 本文なら末尾）。モデル名はこのセッションを動かしている実際のモデル ID を書く
- **簡潔に**。diff やコミット履歴から読めることは書かない。書くのは「なぜ」と、コードからは読めない文脈だけ
- **日本語**。リポジトリの既存 issue / PR が英語なら、それに合わせる（`gh issue list` などで確認）
- **本文と折りたたみで同じことを書かない**。本文の `## 経緯 / 根拠` は結論を支える最小限の箇条書き、折りたたみはそこに至る道筋。重複するなら本文側を削る
- レビュー返信の場合、`## 経緯 / 根拠` は不要なことが多い。「指摘のとおり修正した / この理由で修正しない」を明示し、背景だけ折りたたみに入れる

### Step 5: 書き出してクリップボードにコピーする

本文はワーキングツリー外（`$TMPDIR` またはセッションのスクラッチパッド）に書き出す。リポジトリを汚さないため。

そのうえで、**コピー用のコマンドを 1 つ提示する**。実行はユーザーに任せる。

```bash
pbcopy < /tmp/xxx/comment.md
```

macOS 以外なら `xclip -selection clipboard <` や `wl-copy <` に読み替える。

コマンドと合わせて次を伝える:

- 本文のプレビュー。折りたたみの中身まで含めても 30 行程度に収まっているはずなので、全文を出してよい
- 書き出したファイルのパス。貼り付け後に直したくなったら編集して再コピーできる

## 例

**入力**: 「いまの調査を #17 にコメントしといて」

**出力する本文**:

```markdown
🤖 Claude Code (claude-opus-5)

pre-push フックが遅い原因は、新規ブランチのとき `@{u}..HEAD` が解決できず全履歴を検査していたことでした。マージベースを使う形に直せば解消します。

## 経緯 / 根拠
- upstream 未設定のブランチでは `git rev-list @{u}..HEAD` が全コミットを返す
- 手元の計測で 1,800 コミット走査 → 修正後は 3 コミット
- `--not --remotes` 案も検討したが、複数リモート環境で取りこぼすため不採用

<details>
<summary>背景</summary>

push が体感で数十秒かかるという報告から調査を始めた。`pre-push` フックが対象コミットを `git rev-list @{u}..HEAD` で求めていたが、upstream 未設定の新規ブランチではこの参照が解決できず、全履歴が対象になっていた。手元では 1,800 コミットを走査していた。

対象の絞り込みには `--not --remotes` を使う案もあったが、複数リモートを登録した環境で取りこぼすため採らなかった。既定リモートとのマージベースを起点にする形に変更し、同じブランチで走査対象が 3 コミットになることを確認している。

</details>
```
